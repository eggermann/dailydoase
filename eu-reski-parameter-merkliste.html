Scene-JSON und vollständige Parameterüberschreibungen

Der Runner liest alphabetisch alle Iterationsdateien aus eu-reski-news/scenes/. scene.json enthält nur Zeitplan-Metadaten; jede weitere Datei enthält ein einzelnes Objekt mit name und generationOverrides. Dieses Objekt wird auf eu-reski-news/default-exhibition-settings.json gelegt. Fehlende Werte erben Defaults; CLI-Flags überschreiben JSON-Werte.

Vollständiges Beispiel: scene.json, off-expression.scene.json, on-expression.scene.json mit allen Generationseinstellungen.

scene.json:

{
  "generationIntervalInMinutes": "60",
  "biasMode": "on"
}

off-expression.json oder on-expression.json:

{
  "name": "expression-off",
  "generationOverrides": { "storyClou": "off" }
}

Normaler Start ignoriert Zeitfelder und startet Iterationen ohne Verzögerung. Der Befehl news:exhibition:from-scene-json:with-time-interpolation setzt standardmäßig 1h; CLI-Flag kann Intervall überschreiben. biasMode (on/off) stammt dann aus scene.json.

Startbefehle:

npm run news:exhibition:from-scene-json
npm run news:exhibition:from-scene-json:with-time-interpolation
npm run news:exhibition:from-scene-json:with-time-interpolation -- --generation-interval=2h

Iterationen und Rhythmus

Code-Standardwerte; Starter und Umgebungsvariablen können andere Werte setzen.

ParameterWerte / StandardBedeutung
--iterations1, 2, 3 … · Standard 1Zahl der Nachrichten-Durchgänge. 0 oder -1 läuft endlos.
--scene-count-modefixed oder taktmuster · Standard fixedFester Wert oder ein Taktmusterwert pro Iteration. Der Stream bleibt über Iterationen geöffnet.
--scenes1–12 · Standard 3Feste Szenenzahl im Modus fixed.
--scene-count-takt1–64 · Standard 2Taktmuster für die Szenenzahl.
--scene-count-numerator / --scene-count-denominatorZähler 1–32 · Nenner 1, 2, 4, 8, 16 oder 32Rhythmuswerte für das Szenenzahl-Taktmuster.
--scene-count-typebalanced oder classic · Standard balancedTaktmuster-Typ.
--scene-count-biasGanzzahl · Standard 2Wird zum gerundeten Rohwert addiert; danach wird auf Min./Max. begrenzt.
--min-scenes / --max-scenes1–12 · Standard 1–12Grenzen im Taktmuster-Modus. --scenes wird dort ignoriert.
--pause-msAb 0 · Standard 5000Pause zwischen Iterationen in Millisekunden.
--scene-length-taktPositive Zahl · Standard 4
-1 = GPT		Positiv: Taktmuster gibt Dauerwerte vor. Bei -1 wählt GPT die Sekunden aus dem fixierten Handlungsbogen.
--scene-length-typeStandard balancedMuster-Typ des Taktmuster-Pakets; gilt im Taktmuster-Zeitmodus.
--scene-length-multiplierPositiv · Standard 1.15Multipliziert die Taktmuster-Dauerwerte.
--scene-length-biasZahl · Standard 3.85Addiert einen Sekundenversatz nach dem Multiplikator.
--min-scene-secondsMindestens 5 · Standard 5Untergrenze für die Szenendauer in beiden Zeitmodi.
--max-scene-secondsBis 15 · Standard 8Obergrenze; muss mindestens so groß wie die Untergrenze sein.

News-Takt-Skalierung: Rohwert → Mindestwert 1 → × Multiplikator → + Bias → auf ganze Sekunden runden → auf Min./Max. begrenzen.

Bei GPT-Zeitwahl: Multiplikator, Bias und Muster-Typ werden für die Dauerwahl nicht verwendet. Die Sekunden-Grenzen gelten weiter.

Argumente zum Merken

Diese Argumentgruppen an den vorhandenen Generator-Aufruf anhängen:

Vier Nachrichten; Taktmuster wählt Szenenzahl, GPT wählt Dauer und Bildparameter:

--iterations=4 --scene-count-mode=taktmuster --min-scenes=1 --max-scenes=12
--scene-length-takt=-1 --min-scene-seconds=5 --max-scene-seconds=8
--scene-visual-controls

Vier Iterationen, je fünf Szenen; Taktmuster wählt Dauer, GPT wählt Bildparameter; Videos direkt mit P-Video:

--iterations=4 --scenes=5 --scene-length-takt=4 --scene-length-type=balanced
--scene-length-multiplier=1.15 --scene-length-bias=3.85
--min-scene-seconds=5 --max-scene-seconds=8 --scene-visual-controls
--video-mode=image_to_video --videos-after-each-iteration
--video-model=prunaai:p-video@2-pro --video-resolution=480p --video-settings-mode=cost

Feste Bildparameter für einen Vergleich:

--fixed-visual-controls --symbolic --room-deepness --layering=3
